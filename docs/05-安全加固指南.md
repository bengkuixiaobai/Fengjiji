## 2. 服务器级加固

### 2.1 防火墙（UFW）

```bash
# 安装并启用 UFW
sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing

# 只开放必要端口
sudo ufw allow 22/tcp      # SSH
sudo ufw allow 80/tcp      # HTTP
sudo ufw allow 443/tcp     # HTTPS

# 启用
sudo ufw enable
sudo ufw status verbose
```

### 2.2 云平台安全组

如果使用云服务器，在控制台设置安全组入站规则：

| 协议 | 端口 | 来源 | 说明 |
|------|------|------|------|
| TCP | 22 | 你的 IP（或公司 VPN） | SSH（不要开 0.0.0.0） |
| TCP | 80 | 0.0.0.0/0 | HTTP |
| TCP | 443 | 0.0.0.0/0 | HTTPS |
| TCP | 3000 | ❌ 不开放 | 后端 API 仅 Nginx 本地转发 |
| TCP | 5432 | ❌ 不开放 | PostgreSQL 仅本地监听 |

### 2.3 SSH 加固

```bash
# 禁止 root 登录
sudo sed -i 's/PermitRootLogin yes/PermitRootLogin no/' /etc/ssh/sshd_config

# 禁止密码登录（推荐使用密钥）
sudo sed -i 's/#PasswordAuthentication yes/PasswordAuthentication no/' /etc/ssh/sshd_config

# 修改 SSH 端口（可选，减少扫描）
sudo sed -i 's/#Port 22/Port 2222/' /etc/ssh/sshd_config

# 重启 SSH
sudo systemctl restart sshd
```

### 2.4 自动安全更新

```bash
sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

### 2.5 Fail2ban（防暴力破解 SSH）

```bash
sudo apt install -y fail2ban
sudo systemctl enable fail2ban
sudo systemctl start fail2ban

# 查看封禁状态
sudo fail2ban-client status sshd
```

## 3. 应用级加固

### 3.1 HTTPS 配置

务必通过 Nginx 或云负载均衡配置 HTTPS。参考 [02-环境搭建与部署指南.md](02-环境搭建与部署指南.md) 第 7 节。

使用 Let's Encrypt 免费证书：

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 3.2 JWT 密钥管理

```bash
# 生成强密钥
openssl rand -hex 32 > /var/www/my_website/backend/.jwt-secret
chmod 600 /var/www/my_website/backend/.jwt-secret

# 在 .env 中引用
JWT_SECRET="$(cat /var/www/my_website/backend/.jwt-secret)"
```

### 3.3 PostgreSQL 密码策略

```sql
-- 使用强密码
ALTER USER fengjiji WITH PASSWORD 'your-strong-password-at-least-16-chars';

-- 禁止密码过期（可选）
ALTER USER fengjiji WITH VALID UNTIL 'infinity';
```

### 3.4 系统定期更新

```bash
# 添加到 crontab（每月第 1 个周日凌晨 2 点）
0 2 1-7 * 0 apt update && apt upgrade -y && reboot
```

## 4. 数据库加固

### 4.1 限制监听地址

编辑 `/etc/postgresql/16/main/postgresql.conf`：

```conf
# 只监听本地（禁止外网直连）
listen_addresses = 'localhost'
```

### 4.2 配置客户端认证（pg_hba.conf）

编辑 `/etc/postgresql/16/main/pg_hba.conf`：

```conf
# 仅允许本地用户通过密码连接
local   all             all                                     md5
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
# 禁止所有外网连接
host    all             all             0.0.0.0/0               reject
host    all             all             ::0/0                   reject
```

### 4.3 数据库备份

参考 [03-运维与备份手册.md](03-运维与备份手册.md) 第 3 节。建议：

- 每日全量备份（custom 格式）
- 保留 30 天
- 每周验证备份完整性
- 定期将备份同步到异地

## 5. 监控与告警

### 5.1 简易健康检查

```bash
# 检测 API 是否返回 200，失败时发邮件
*/5 * * * * curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/health | grep -q 200 || echo "API 挂了" | mail -s "Alert" your-email@example.com
```

### 5.2 磁盘监控

```bash
# 磁盘使用率超过 80% 时告警
*/10 * * * * df -h / | awk 'NR==2 {gsub(/%/,"",$5); if ($5 > 80) print "磁盘使用率 " $5 "%"}' | mail -s "Disk Alert" your-email@example.com
```

### 5.3 使用 PM2 Web 面板（可选）

```bash
pm2 plus
```

## 安全事件响应流程

### 如果发现被入侵

1. **立即断开网络**：在云控制台关闭服务器或设置安全组禁止所有入站
2. **保留现场**：不要重启服务器，保存内存和进程信息
3. **分析入侵路径**：
   - 检查 `auth.log`、`pm2 logs`、Nginx 日志
   - 检查是否有未知进程（`ps aux`）
   - 检查文件修改时间（`find / -mtime -1 -type f`）
4. **从备份恢复**：
   - 重装系统
   - 恢复数据库备份
   - 恢复代码（从 Git 重新 clone）
5. **修改所有密码**：服务器、数据库、JWT、DNS 管理后台

### 日常预防

- 保持系统和依赖更新
- 不要使用 root 运行服务
- 定期轮换 JWT 密钥
- 定期检查审计日志
- 最小权限原则
