## 1. 日常运维命令

### PM2 进程管理

```bash
# 查看进程状态
pm2 list

# 查看日志
pm2 logs fengjiji-api          # 实时日志
pm2 logs fengjiji-api --lines 100  # 最近 100 行

# 重启
pm2 restart fengjiji-api

# 重新加载（0 宕机时间）
pm2 reload fengjiji-api

# 停止/启动
pm2 stop fengjiji-api
pm2 start fengjiji-api

# 查看进程详情
pm2 show fengjiji-api

# 监控（CPU/内存/请求）
pm2 monit

# 保存当前进程列表（下次重启自动恢复）
pm2 save
```

### 系统监控

```bash
# 磁盘
df -h

# 内存
free -h

# CPU 和进程
top -bn1 | head -20

# 端口监听
ss -tlnp

# Nginx 连接数
ss -tn | grep ':443' | wc -l
```

## 2. 日志管理

### 日志位置

| 类型 | 路径 |
|------|------|
| PM2 标准输出 | `/var/www/my_website/logs/api-out.log` |
| PM2 错误日志 | `/var/www/my_website/logs/api-error.log` |
| Nginx 访问日志 | `/var/log/nginx/access.log` |
| Nginx 错误日志 | `/var/log/nginx/error.log` |
| PostgreSQL 日志 | `/var/log/postgresql/postgresql-16-main.log` |

> PM2 日志已配置自动轮转（最大 10MB，保留 10 份），见 [ecosystem.config.js](../ecosystem.config.js)。

### Nginx 日志轮转

Nginx 默认使用 `logrotate`，配置在 `/etc/logrotate.d/nginx`，通常已自动启用。

### 手动清理

```bash
# 查看日志大小
du -sh /var/www/my_website/logs/

# 清理所有历史日志（保留最近一次）
sudo journalctl --vacuum-size=200M

# 截断 PM2 日志（不影响运行）
pm2 flush
```

## 3. 数据库备份与恢复

### 自动备份脚本

创建 `/var/www/my_website/scripts/backup-db.sh`：

```bash
#!/bin/bash
# 数据库备份脚本 — 每日凌晨执行
# 配置 cron: 0 3 * * * /var/www/my_website/scripts/backup-db.sh

set -e

# ===== 配置 =====
BACKUP_DIR="/var/backups/fengjiji"
DB_NAME="fengjiji"
DB_USER="fengjiji"
RETENTION_DAYS=30
TIMESTAMP=$(date +%Y%m%d_%H%M%S)

# ===== 创建备份目录 =====
mkdir -p "$BACKUP_DIR"

# ===== 执行备份 =====
pg_dump -U "$DB_USER" -d "$DB_NAME" \
  --format=custom \
  --file="${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.dump" \
  --verbose 2>>"${BACKUP_DIR}/backup.log"

# ===== 压缩（可选，custom 格式已压缩）=====
gzip -f "${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.dump"

# ===== 清理过期备份 =====
find "$BACKUP_DIR" -name "${DB_NAME}_*.dump.gz" -mtime +$RETENTION_DAYS -delete

# ===== 验证备份完整性 =====
LATEST=$(ls -t "${BACKUP_DIR}/${DB_NAME}_"*.dump.gz 2>/dev/null | head -1)
if [ -n "$LATEST" ]; then
  gunzip -c "$LATEST" | pg_restore --list > /dev/null 2>&1 \
    && echo "[OK] 备份验证通过: $(basename $LATEST)" \
    || echo "[FAIL] 备份验证失败: $(basename $LATEST)"
fi

echo "[DONE] $(date) - 备份完成"
```

### 配置定时任务

```bash
# 赋予执行权限
chmod +x /var/www/my_website/scripts/backup-db.sh

# 编辑 crontab
sudo crontab -e -u fengjiji
```

添加：

```cron
# 每天凌晨 3:00 备份数据库
0 3 * * * /var/www/my_website/scripts/backup-db.sh

# 每周日凌晨 4:00 重启后端（内存清理）
0 4 * * 0 pm2 restart fengjiji-api
```

### 恢复数据库

```bash
# 查找要恢复的备份
ls -lh /var/backups/fengjiji/

# 恢复
gunzip -c /var/backups/fengjiji/fengjiji_20260630_030001.dump.gz | pg_restore -U fengjiji -d fengjiji --clean --if-exists

# 或分步操作：
# 1. 先创建空数据库
sudo -u postgres createdb fengjiji_restore
# 2. 恢复
pg_restore -U fengjiji -d fengjiji_restore /var/backups/fengjiji/fengjiji_20260630_030001.dump
```

### 备份同步到远程（可选）

如果你有另一台服务器或对象存储，可将备份同步到远端：

```bash
# 在 backup-db.sh 末尾添加：
# 上传到对象存储（需要 rclone 或 aws-cli）
rclone copy "$BACKUP_DIR" remote:backup-bucket/fengjiji-db/ --include "*.dump.gz"

# 或 scp 到另一台服务器
# scp "${BACKUP_DIR}/${DB_NAME}_${TIMESTAMP}.dump.gz" user@backup-server:/backups/
```

## 5. 故障恢复

### 场景 A：服务器宕机/重启

```bash
# 检查所有服务
pm2 list
sudo systemctl status nginx
sudo systemctl status postgresql

# 如果 PM2 进程丢失
pm2 start /var/www/my_website/ecosystem.config.js --env production

# 如果 PostgreSQL 未启动
sudo systemctl start postgresql
```

### 场景 B：磁盘空间满

```bash
# 快速释放空间
df -h
du -sh /var/log/
du -sh /var/www/my_website/logs/

# 清理 PM2 日志
pm2 flush

# 清理 Nginx 日志
sudo truncate -s 0 /var/log/nginx/access.log
sudo truncate -s 0 /var/log/nginx/error.log

# 清理 journalctl
sudo journalctl --vacuum-size=100M

# 清理 Docker 残留（如果使用过）
docker system prune -f
```

### 场景 C：SSL 证书过期

```bash
# 手动续期
sudo certbot renew

# 检查自动续期是否正常
sudo systemctl status certbot.timer

# 如果 certbot 自动续期失败，检查日志
sudo tail -f /var/log/letsencrypt/letsencrypt.log
```

### 场景 D：数据库损坏

```bash
# 1. 停止后端
pm2 stop fengjiji-api

# 2. 恢复最近备份
gunzip -c /var/backups/fengjiji/fengjiji_20260630_030001.dump.gz | pg_restore -U fengjiji -d fengjiji --clean --if-exists

# 3. 重启后端
pm2 start fengjiji-api

# 4. 验证数据
curl https://your-domain.com/api/posts?limit=5
```

### 场景 E：应用代码崩溃

```bash
# 查看错误日志
pm2 logs fengjiji-api --lines 50 --err

# 回滚到上一个 Git 版本
cd /var/www/my_website
git log --oneline -5
git checkout <上一个正常commit的hash>
pm2 restart fengjiji-api

# 如果构建产物有问题，重建前端
cd frontend && npm run build
```

## 6. 监控

### 简易健康检查（cron）

```bash
# 每分钟检测 API 是否存活，失败则重启
* * * * * curl -s -o /dev/null -w "%{http_code}" http://localhost:3000/api/health | grep -q 200 || pm2 restart fengjiji-api
```

### PM2 监控面板

```bash
# 终端监控
pm2 monit

# Web 监控（Keymetrics，需要注册）
pm2 plus
```

### 手动检查

```bash
# 一键健康检查脚本
cat << 'EOF' | bash
echo "=== 进程检查 ==="
pm2 list | grep fengjiji
sudo systemctl is-active nginx
sudo systemctl is-active postgresql

echo "=== 端口检查 ==="
ss -tlnp | grep -E ':3000|:443|:80|:5432'

echo "=== 磁盘 ==="
df -h / | tail -1

echo "=== 内存 ==="
free -h | grep Mem

echo "=== API 健康 ==="
curl -s http://localhost:3000/api/health
EOF
```
