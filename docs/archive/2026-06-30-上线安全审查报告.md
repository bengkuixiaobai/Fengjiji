## 2. 🚨 严重风险（必须修复）

### CRIT-1: `PostLike.toggleLike` 调用不存在字段 `id` ⚡

- **文件**：[backend/src/services/post.service.js:399](backend/src/services/post.service.js#L399)
- **代码**：
  ```js
  await prisma.postLike.delete({ where: { id: existing.id } })
  ```
- **问题**：`PostLike` 模型使用复合主键 `@@id([postId, visitorId])`，**没有 `id` 字段**。`existing.id` 是 `undefined`，Prisma 会抛出异常。
- **影响**：点赞**取消功能完全不可用**，点击已点赞的文章会直接报错 500。
- **修复**：
  ```js
  // 改为使用复合主键删除
  await prisma.postLike.delete({
    where: {
      postId_visitorId: { postId: id, visitorId },
    },
  })
  ```

### CRIT-2: Seed 脚本使用错误字段名 `passwordHash`

- **文件**：[backend/prisma/seed.js:39](backend/prisma/seed.js#L39)
- **代码**：
  ```js
  const user = await prisma.user.create({
    data: {
      username: ADMIN.username,
      email: ADMIN.email,
      passwordHash,   // ❌ schema 中字段名是 password，不是 passwordHash
      nickname: ADMIN.nickname,
      role: 'admin',
    },
  })
  ```
- **影响**：运行 seed 脚本时 Prisma 会抛出 `Unknown argument` 错误，**管理员账号创建失败**。首次部署后无法登录。
- **修复**：将 `passwordHash` 改为 `password: passwordHash`

### CRIT-3: 没有 HTTPS 强制跳转

- **文件**：[backend/src/app.js](backend/src/app.js)
- **问题**：生产模式下没有将 HTTP 请求 301 重定向到 HTTPS。
- **风险**：如果前端通过 HTTP 访问，密码和 token 明文传输，可被中间人攻击窃取。
- **建议**：在 Nginx 层做 HTTPS 重定向，或者在 Express 中添加：
  ```js
  if (config.nodeEnv === 'production') {
    app.use((req, res, next) => {
      if (!req.secure && req.headers['x-forwarded-proto'] !== 'https') {
        return res.redirect(301, `https://${req.headers.host}${req.url}`)
      }
      next()
    })
  }
  ```

## 3. 🔴 高危风险

### HIGH-1: 缺少安全响应头（Helmet）

- **文件**：[backend/src/app.js](backend/src/app.js)
- **问题**：没有使用 `helmet` 中间件，缺少以下安全头：
  - `X-Frame-Options` — 防止点击劫持
  - `X-Content-Type-Options` — 防止 MIME 嗅探
  - `Content-Security-Policy` — 防止 XSS 和数据注入
  - `Strict-Transport-Security` — 强制 HTTPS
  - `X-XSS-Protection` — XSS 过滤
- **建议**：
  ```bash
  npm install helmet
  ```
  ```js
  // app.js
  const helmet = require('helmet')
  app.use(helmet())
  ```

### HIGH-2: JWT 和 refreshToken 存 localStorage

- **文件**：[frontend/src/services/apiClient.ts:16](frontend/src/services/apiClient.ts#L16)
- **代码**：
  ```ts
  const token = localStorage.getItem('auth-token')
  ```
- **风险**：localStorage 无法设置 HttpOnly，如果页面存在 XSS 漏洞（比如通过 Markdown 注入），攻击者可窃取 token。
- **影响**：攻击者可获取用户身份，以管理员身份操作。
- **建议**：
  - 短期方案：确保 `react-markdown` 默认不渲染 HTML（它默认安全，但要确认）
  - 长期方案：将 token 迁移到 httpOnly cookie，由后端设置
  - 代码本身在 mock posts 文件中也有注释提示此问题

### HIGH-3: 上传文件仅验证扩展名

- **文件**：[backend/src/routes/upload.routes.js:21-28](backend/src/routes/upload.routes.js#L21-L28)
- **代码**：
  ```js
  fileFilter: (req, file, cb) => {
    const allowed = /\.(jpg|jpeg|png|gif|webp|svg)$/i
    if (allowed.test(path.extname(file.originalname))) {
      cb(null, true)
    }
  ```
- **风险**：仅检查扩展名，不验证文件内容 MIME type。`.exe` 改名为 `.jpg` 即可上传。
- **影响**：恶意文件上传后可被直接访问，可能导致服务器沦陷。
- **建议**：
  ```bash
  npm install file-type
  ```
  在上传后校验文件真实类型：
  ```js
  const type = await fileType.fromFile(file.path)
  if (!type || !['image/jpeg', 'image/png', 'image/gif', 'image/webp', 'image/svg+xml'].includes(type.mime)) {
    fs.unlinkSync(file.path)
    return res.status(400).json({ error: '文件类型不合法' })
  }
  ```

### HIGH-4: 管理员密码明文打印到控制台

- **文件**：[backend/prisma/seed.js:44-49](backend/prisma/seed.js#L44-L49)
- **代码**：
  ```js
  console.log(`     password: ${ADMIN.password}`)
  ```
- **风险**：如果 seed 脚本在服务器上运行（`node prisma/seed.js`），密码会写入日志文件。日志可能被其他人看到。
- **建议**：删除打印密码的 log，改为：
  ```js
  console.log(`     密码已设置 (安全起见不在日志中显示)`)
  ```

## 4. 🟡 中危风险

### MED-1: 上传路径没有文件名消毒

- **文件**：[backend/src/routes/upload.routes.js:11-14](backend/src/routes/upload.routes.js#L11-L14)
- **代码**：
  ```js
  filename: (req, file, cb) => {
    const unique = Date.now() + '-' + Math.round(Math.random() * 1e9)
    const ext = path.extname(file.originalname)
    cb(null, unique + ext)
  },
  ```
- **风险**：虽然用了随机文件名，但 `path.extname` 对恶意文件名如 `shell.jpg.exe` 或 `test.js†.png`（Unicode 欺骗）可能提取错误。不过此场景风险较低。
- **建议**：白名单允许的扩展名，抛弃原文件名后缀，只用 `.jpg`/`.png`/`.webp` 等已知后缀。

### MED-2: Prisma `contains` 查询无长度限制

- **文件**：[backend/src/services/post.service.js:41-44](backend/src/services/post.service.js#L41-L44)
- **代码**：
  ```js
  if (search) {
    where.OR = [
      { title: { contains: search, mode: 'insensitive' } },
      { summary: { contains: search, mode: 'insensitive' } },
    ]
  }
  ```
- **风险**：超长搜索字符串可能造成数据库性能问题。`insensitive` 模式在 PostgreSQL 中不会使用索引（`LIKE '%...%'` 本身无法走 B-tree 索引）。
- **建议**：对 `search` 参数做长度限制（前端已做，后端未做），建议添加：
  ```js
  if (search && search.length > 100) {
    search = search.slice(0, 100)
  }
  ```

### MED-3: 登陆接口用户名枚举

- **文件**：[backend/src/services/auth.service.js:90-97](backend/src/services/auth.service.js#L90-L97)
- **代码**：
  ```js
  if (!user) {
    throw { code: 'INVALID_CREDENTIALS', message: '用户名/邮箱或密码错误' }
  }
  const isValid = await bcrypt.compare(password, user.password)
  if (!isValid) {
    throw { code: 'INVALID_CREDENTIALS', message: '用户名/邮箱或密码错误' }
  }
  ```
- **分析**：✅ 目前实现是正确的——用户不存在和密码错误返回相同错误信息，不会暴露用户名是否存在。但要注意确保响应时间差异不泄露信息（由于 Prisma 查询和 bcrypt.compare 时间差异，理论上还是有时序侧信道）。

### MED-4: `pm2 start` 或 `node index.js` 没有 `--unhandled-rejections` 处理

- **风险**：未捕获的 Promise rejection 会导致进程退出。当前代码中所有 async handler 都用了 `try/catch` + `next(error)`，但如果有遗漏，PM2 默认会重启进程。
- **建议**：在 `index.js` 或 `server.js` 中添加：
  ```js
  process.on('unhandledRejection', (reason) => {
    console.error('未捕获的 Promise 拒绝:', reason)
  })
  ```

### MED-5: 数据库连接字符串含密码

- **文件**：[backend/.env](backend/.env)
- **代码**：
  ```env
  DATABASE_URL="postgresql://postgres:123456@localhost:5432/fengjiji?schema=public"
  ```
- **风险**：密码 `123456` 是弱密码，且 `.env` 可能被意外提交到 Git（当前已被 `.gitignore` 排除，但需确认）。
- **建议**：将 PostgreSQL 密码改为强密码（至少 16 位随机字符）。

## 5. 🟢 低危 / 建议

### LOW-1: 搜索用 `LIKE %...%` 性能问题

- **文件**：[backend/src/services/post.service.js:42](backend/src/services/post.service.js#L42)
- **建议**：数据量大时（>1万篇文章），建议改用 PostgreSQL 全文搜索（`tsvector`）或外部搜索服务。

### LOW-2: Prisma JSON 字段手动 parse

- **文件**：[backend/src/services/project.service.js](backend/src/services/project.service.js)
- **风险**：多处手动 `JSON.parse(project.techStack)` 如果存入的不是合法 JSON 会崩溃。
- **建议**：Prisma 在 5.x 支持 PostgreSQL 的 JSON 类型，可将 `techStack` 和 `plan` 字段改为 `Json` 类型（需要 migration），由 Prisma 自动序列化/反序列化。

### LOW-3: Access Token 有效期 15 分钟偏短

- **文件**：[backend/.env](backend/.env)
- **代码**：`JWT_EXPIRES_IN="15m"`
- **建议**：个人博客建议设为 1 小时，减少不必要的 refresh 请求。15 分钟更适合高安全场景。

### LOW-4: 没有请求体大小限制

- **文件**：[backend/src/app.js:14](backend/src/app.js#L14)
- **建议**：对 `express.json()` 添加限制，防止超大请求体：
  ```js
  app.use(express.json({ limit: '1mb' }))
  app.use(express.urlencoded({ extended: true, limit: '1mb' }))
  ```

### LOW-5: 没有日志轮转策略

- **建议**：PM2 的日志默认无上限增长，建议在 `ecosystem.config.js` 中配置：
  ```js
  module.exports = {
    apps: [{
      name: 'fengjiji-api',
      script: 'index.js',
      max_memory_restart: '500M',
      log_date_format: 'YYYY-MM-DD HH:mm:ss',
      merge_logs: true,
      max_size: '10M',
      retain: 10,
    }]
  }
  ```

## 6. 防御体系评分

| 攻击类型 | 防护状态 | 说明 |
|----------|----------|------|
| **SQL 注入** | ✅ 安全 | Prisma ORM 参数化查询，无原生 SQL |
| **XSS (存储型)** | ✅ 基本安全 | `react-markdown` 默认不渲染 HTML |
| **XSS (反射型)** | ⚠️ 部分安全 | 缺少 CSP 头 + token 存 localStorage |
| **CSRF** | ✅ 安全 | JWT Bearer token 天然防 CSRF |
| **暴力登录** | ✅ 已防护 | `express-rate-limit` 已配置 |
| **点击劫持** | ❌ 未防护 | 缺少 `X-Frame-Options` |
| **MIME 嗅探** | ❌ 未防护 | 缺少 `X-Content-Type-Options` |
| **中间人攻击** | ⚠️ 部分防护 | 需要 Nginx 层配 HTTPS |
| **密码暴力破解** | ✅ 已防护 | Joi 校验 + rate limit |
| **文件上传漏洞** | ❌ 未完全防护 | 仅检查扩展名 |
| **JWT 伪造** | ✅ 已防护 | 生产环境强制强密钥 |
| **DDOS** | ❌ 未防护 | 应用层无 IP 频率限制 |
| **用户枚举** | ✅ 已防护 | 统一错误信息 |
| **路径遍历** | ✅ 安全 | Express `express.static` 安全，multer 随机文件名 |
