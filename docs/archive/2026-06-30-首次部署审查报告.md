## P0 — 阻塞部署（必须修复）

### 1. 后端缺少 4 个 API 路由

前端已调用但后端未实现，部署后这些功能会报 404：

| 前端调用 | 后端缺失 | 影响 |
|----------|----------|------|
| `POST /posts/:id/view` | 记录阅读量 | 博客详情页浏览数不增加 |
| `POST /posts/:id/like/toggle` | 切换点赞 | 点赞按钮无效 |
| `GET /posts/:id/like/status` | 获取点赞状态 | 点赞状态不显示 |
| `GET /posts/:id/adjacent` | 上下篇导航 | 文章底部导航不显示 |

**对应前端文件**：[frontend/src/services/post.ts](frontend/src/services/post.ts#L104-L145)
**需修改后端文件**：[backend/src/routes/post.routes.js](backend/src/routes/post.routes.js) → 新增 4 个路由 + 对应 controller/service 方法

- **影响**：首次部署后无法登录（注册需要邀请码，但没有用户来生成邀请码）

## P1 — 部署前建议修复

### 5. 错误 import 路径

| 文件 | 错误引用 | 应改为 |
|------|----------|--------|
| [BlogManage.tsx:19](frontend/src/pages/BlogManage.tsx#L19) | `import apiClient from '../services/auth'` | `'../services/apiClient'` |

目前能用是因 `auth.ts` re-export 了 `apiClient`，但语义不正确，后续重构容易断。

---

### 6. Tag 按 slug 查询不匹配

- **前端**：[frontend/src/services/tag.ts:23](frontend/src/services/tag.ts#L23) → 调用 `GET /tags/${slug}`
- **后端**：[backend/src/routes/tag.routes.js:55](backend/src/routes/tag.routes.js#L55) → 仅支持 `GET /tags/:id`（按数字 ID）
- **影响**：分类页/标签页的 slug 路由无法正确加载

---

### 7. Refresh Token 自动续期未实现

- **前端**：[frontend/src/services/apiClient.ts](frontend/src/services/apiClient.ts#L27-L36)
- **问题**：拦截器收到 401 直接清除 token 跳转登录页，不尝试用 refreshToken 续期
- **影响**：用户每 15 分钟（token 有效期）就会被强制登出
- **后端已有对应接口**：`POST /auth/refresh`

---

### 8. 通知/消息系统纯 Mock

- **前端文件**：[frontend/src/pages/Notifications.tsx](frontend/src/pages/Notifications.tsx)、[frontend/src/services/notifications.ts](frontend/src/services/notifications.ts)
- **问题**：整个通知中心（联系人、消息、好友申请、通知、关注）**完全基于前端 mock 数据**，没有后端 API 支撑
- **影响**：部署后用不了，且数据库 schema 中没有对应的表模型

---

### 9. 部分用户偏好仅存 localStorage

- **文件**：[frontend/src/pages/Settings.tsx](frontend/src/pages/Settings.tsx)
- **涉及设置**：博客排序方式、封面显示、Markdown 字体大小
- **问题**：只存在浏览器 `localStorage`，更换设备或清除缓存后丢失
- **建议**：如果有用户设置表，可持久化到后端

## P2 — 建议补充功能

### 10. Tag/Category 缺少更新和查询接口

后端目前仅支持创建和查询/删除，缺少以下操作：

| 接口 | 说明 |
|------|------|
| `PUT /tags/:id` | 重命名标签 |
| `PUT /categories/:id` | 重命名分类 |

| `PUT /categories/:id/sort` | 调整分类排序 |

### 11. 缺少评论系统

- 数据库 schema 中没有 `Comment` 模型
- 博客详情页（BlogDetail）下方没有评论区
- 作为个人博客，评论是最基础的互动功能

---

### 12. 前端 .env.example 缺变量

- **文件**：[frontend/.env.example](frontend/.env.example)
- **当前内容**：只有 `VITE_API_BASE_URL=/api`
- **缺少**：`VITE_USE_MOCK=false` —— 部署后应该关闭 mock

---

### 13. 缺少根目录一键管理脚本

目前启动/构建需要分别进入 `backend/` 和 `frontend/` 执行命令。建议在根目录添加 `package.json`：

```json
{
  "scripts": {
    "install:all": "cd backend && npm install && cd ../frontend && npm install",
    "dev": "cd backend && npm run dev & cd ../frontend && npm run dev",
    "build": "cd frontend && npm run build",
    "start": "cd backend && npm start",
    "deploy": "npm run build && npm run start"
  }
}
```

## P3 — 安全与生产配置

### 14. JWT_SECRET 默认值过于简单

- **文件**：[backend/src/config/index.js:9](backend/src/config/index.js#L9)
- **代码**：`JWT_SECRET || 'default-secret-key'`
- **风险**：若部署时忘记设置环境变量，JWT 密钥是公开的字符串，任何人都可以伪造 token
- **建议**：部署前务必设置强随机字符串（可用 `openssl rand -hex 32` 生成）

---

### 15. 上传文件校验不够严格

- **文件**：[backend/src/routes/upload.routes.js:22](backend/src/routes/upload.routes.js#L22)
- **问题**：只检查了文件扩展名（白名单），没有校验文件内容的 MIME type
- **风险**：恶意文件可通过修改扩展名绕过检查
- **建议**：增加 `file-type` 或 `mime` 库进行内容检验

---

### 16. 登录接口缺少频率限制

- **文件**：[backend/src/routes/auth.routes.js](backend/src/routes/auth.routes.js#L68)
- **问题**：`POST /auth/login` 没有 rate limiting
- **风险**：可被暴力破解密码
- **建议**：添加 `express-rate-limit` 中间件，限制单 IP 每分钟最多 5 次登录尝试

---

### 17. CORS 生产环境全开放

- **文件**：[backend/src/app.js:12](backend/src/app.js#L12)
- **代码**：`app.use(cors())`
- **问题**：所有域名都可跨域访问 API
- **建议**：生产环境下限制为具体的前端域名

---

### 18. 缺少基础设施配置

部署到生产环境前仍需要以下配置：

| 项目 | 说明 |
|------|------|
| **Nginx 配置** | 反向代理、HTTPS、静态文件服务 |
| **PM2 配置** | 进程守护、自动重启、日志管理 |
| **Docker 配置**（可选） | `Dockerfile` + `docker-compose.yml` |
| **数据库备份** | 定期备份 PostgreSQL 的策略 |
| **日志轮转** | 防止日志无限增长占满磁盘 |
| **监控告警** | 服务宕机通知 |
