## 1. 启动问题

### Q: `npm start` 报错 "port 3000 已被占用"

```bash
# 查找占用 3000 端口的进程
ss -tlnp | grep :3000
lsof -i :3000

# 杀掉占用进程
kill -9 <PID>

# 或改用其他端口
PORT=3001 npm start
```

### Q: 启动后立即退出，控制台没有错误信息

```bash
# 查看 PM2 错误日志
pm2 logs fengjiji-api --err --lines 50

# 直接运行查看错误输出（不用 PM2）
cd backend && NODE_ENV=production node index.js
```

常见原因：
- JWT_SECRET 不符合要求（见 [04-环境变量参考.md](04-环境变量参考.md)）
- DATABASE_URL 格式错误
- 数据库连接不上

### Q: PM2 进程状态为 "errored"（红色）

```bash
# 查看原因
pm2 logs fengjiji-api --lines 20 --err

# 查看进程详细信息
pm2 show fengjiji-api

# 常见原因及修复：
# 1. 端口被占用 → 杀掉占用进程或换端口
# 2. 数据库连接失败 → 检查 PostgreSQL 是否运行
# 3. JWT 密钥问题 → 检查 .env 配置

# 修复后重启
pm2 restart fengjiji-api
```

## 2. 数据库问题

### Q: 连接数据库报错 "password authentication failed"

```bash
# 检查 .env 中的 DATABASE_URL 密码是否正确
cat backend/.env | grep DATABASE_URL

# 用 psql 测试连接（需要输入密码）
PGPASSWORD='你的密码' psql -U fengjiji -d fengjiji -h localhost

# 重设密码
sudo -u postgres psql -c "ALTER USER fengjiji WITH PASSWORD '新密码';"

# 更新 .env 中的 DATABASE_URL
```

### Q: `npx prisma migrate deploy` 报错 "can't reach database server"

```bash
# 检查 PostgreSQL 是否运行
sudo systemctl status postgresql

# 检查监听地址
sudo -u postgres psql -c "SHOW listen_addresses;"

# 检查端口
ss -tlnp | grep 5432

# 启动 PostgreSQL
sudo systemctl start postgresql
```

### Q: `npx prisma generate` 报错 "schema not found"

```bash
# 确认在 backend 目录下
cd backend

# 检查 schema 文件是否存在
ls prisma/schema.prisma

# 重新生成
npx prisma generate
```

### Q: seed 脚本运行失败

```bash
# 试着手动运行，看具体错误
cd backend
node prisma/seed.js

# 常见原因（已修复）：
# - seed.js 中使用了 passwordHash 字段名（旧版本 bug）
# - bcrypt 安装失败

# 重置种子数据（如果要重新运行）
npx prisma migrate reset --force
```

## 3. 前端问题

### Q: 页面空白，控制台报 404

```
GET /api/posts 404 (Not Found)
```

可能原因：
- 后端未启动 → `pm2 list` 检查
- Nginx 未正确反向代理 → 检查 `/etc/nginx/sites-enabled/fengjiji`
- `VITE_API_BASE_URL` 设置不正确

### Q: 登录后马上被登出（约 15 分钟）

- Access Token 默认有效期 15 分钟
- 正常情况会自动静默续期（`apiClient.ts` 已实现 refresh 逻辑）
- 如果还是被登出，检查 `POST /api/auth/refresh` 是否正常返回
- 可调长 `.env` 中的 `JWT_EXPIRES_IN` 为 `1h`

### Q: 前端显示 Mock 数据而非真实数据

```bash
# 检查 frontend/.env
cat frontend/.env

# 确保已设置
VITE_USE_MOCK=false

# 重新构建
cd frontend && npm run build
```

### Q: 构建失败 "TypeScript 类型错误"

```bash
# 跳过类型检查构建（如果类型问题不影响运行）
npx tsc --noEmit  # 先查看具体错误

# 如果只是类型定义问题，可以：
npm run build 2>&1 | head -30  # 查看具体错误

# 常见修复：
# - 安装缺失的 @types 包
# - 修正 import 路径
```

### Q: 页面样式错乱（浅色/深色模式切换异常）

- 清除浏览器缓存（localStorage 中持久化了主题设置）
- 打开控制台 → Application → Local Storage → 删除 `theme-storage`
- 刷新页面

## 4. 性能问题

### Q: 页面加载慢

| 原因 | 解决方案 |
|------|----------|
| 图片未压缩 | 上传前压缩图片，建议 WebP 格式 |
| 3M 带宽瓶颈 | 启用 Nginx Gzip 压缩（已在配置中启用） |
| API 响应慢 | 检查 Prisma 查询，看数据库索引 |
| 首次打开慢 | 前端已配置路由级 lazy loading + 代码分包 |

### Q: 后端内存持续增长（疑似泄漏）

```bash
# 监控内存
pm2 monit

# 查看进程详情
pm2 show fengjiji-api

# 设置内存上限自动重启（已配置 500M）
# 应急：手动重启
pm2 restart fengjiji-api

# 找到泄漏点（需要 Node.js 调试）
node --inspect index.js  # 用 Chrome DevTools 连接
```

### Q: 数据库查询越来越慢

```bash
# 检查慢查询
sudo -u postgres psql -c "SELECT * FROM pg_stat_activity WHERE state = 'active';"

# 启用 PostgreSQL 慢查询日志
sudo -u postgres psql -c "SET log_min_duration_statement = 1000;"  # 记录超过 1 秒的查询

# 查看表大小
sudo -u postgres psql -d fengjiji -c "SELECT relname, n_live_tup FROM pg_stat_user_tables ORDER BY n_live_tup DESC;"
```

## 5. 安全相关问题

### Q: 收到 "JWT_SECRET" 相关错误

```bash
# 生成新密钥
openssl rand -hex 32

# 更新 backend/.env
JWT_SECRET="新生成的64字符十六进制字符串"

# 重启后端
pm2 restart fengjiji-api

# 注意: 更换 JWT_SECRET 会使所有已签发的 token 失效，所有用户需要重新登录
```

### Q: 怀疑服务器被入侵

立即执行：

```bash
# 1. 云控制台设置安全组，禁止所有入站流量
# 2. 查看最近登录记录
last -10

# 3. 查看正在运行的进程
ps aux --sort=-%mem | head -20

# 4. 查看可疑网络连接
ss -tlnp

# 5. 查看最近修改的文件
find /var/www -mtime -1 -type f

# 6. 检查定时任务
crontab -l
sudo crontab -l
```

### Q: 如何验证安全配置是否生效

```bash
# 检查安全响应头
curl -sI https://your-domain.com | grep -E 'X-Frame|X-Content|X-XSS|Content-Security|Strict-Transport'

# 预期应包含：
# X-Frame-Options: SAMEORIGIN
# X-Content-Type-Options: nosniff
# Content-Security-Policy: default-src 'self'; ...

# 检查 HTTPS 证书
curl -vI https://your-domain.com 2>&1 | grep -i 'ssl\|tls\|certificate'
```
